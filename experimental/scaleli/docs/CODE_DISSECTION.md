# Storage layout, build and memory accounting

SCALE-LI is a two-level structure: the canonical (sorted, deduplicated) key set is cut into consecutive regions of 4096 keys, and each region is cut into consecutive blocks of 128 keys. Each region is a separately heap-allocated `Region` of 280 B that holds its own byte arena of encoded key blocks, an uncompressed `uint64` value column, a 64 B `BlockDescriptor` per block, a sorted delta buffer, two 32 B linear models (rank and byte) and, with CSV smoothing, the persisted virtual-point features. Every block is encoded first: Raw is the baseline, and `min_bytes` keeps the smallest of FOR, Delta and Linear only if it saves at least 5% over Raw. After that the region computes its features (normalized key or flow), optionally runs NFL-style flow selection and CSV smoothing, and then fits both models by single-pass long-double OLS on real keys only. So the key arena does not depend on flow or virtual points. `--build-threads` parallelizes only the per-region rebuilds; canonicalization and the root fit (`fit_root`, including root virtual-fence smoothing) run single-threaded. `memory()` adds up live sizes in 5 fields: key, value, metadata, delta and slack. At 200M keys the metadata is exactly 114,063,088 B (0.570 B/key). Values cost 8 B/key, and virtual points add 8 B each in metadata. Not counted: flow weights, `virtual_features` capacity slack, root-table capacity and allocator overhead.

## Facts

- [✓] **Canonicalisation**: canonicalize() runs std::stable_sort on Record by key, then dedups in place: if key == previous, it overwrites the previous value, so the last input write wins. No sentinel key or value is reserved. It is applied to the raw input (make_workload), again to w.initial, and a third time inside Index::bulk_load. (include/scaleli/types.hpp:80-89; include/scaleli/workload.hpp:108,113; include/scaleli/index.hpp:454)
- [✓] **Values**: Values are not read from the dataset. The SOSD reader sets value = mix64(i), with i the key's 0-based position in the file. The value column is stored uncompressed: a per-region std::vector<Value> (uint64) in key order, addressed as values[block.rank_begin + in-block index]. (include/scaleli/workload.hpp:47; include/scaleli/index.hpp:92,168,211)
- [unchecked] **Region partition**: Regions are consecutive chunks of region_keys canonical rows (default 4096). Region j holds rows [4096j, min(4096(j+1), n)). low_fence = rows[4096j].first, except region 0, whose fence is 0. At n = 200,000,000 this gives ceil(n/4096) = 48,829 regions, and the last region holds 200,000,000 - 48,828*4096 = 512 keys (derived). (include/scaleli/index.hpp:44,456-458; src/benchmark.cpp:268)
- [✓] **Block partition**: Inside each region, blocks are consecutive chunks of block_keys keys (default 128), starting at region-local rank 0. Blocks never span regions. At 200M: 32 blocks per full region, 4 in the 512-key region, 1,562,500 in total (= 200M/128 exactly). (include/scaleli/index.hpp:44,213-214; results/aidb_ba/memory_audit.md:29)
- [unchecked] **Config validation**: validate() requires 1 <= block_keys <= region_keys <= 16,777,216, delta_limit > 0 and <= 2*region_keys, restart_interval in [1, 65535], virtual_alpha in [0,1), root_alpha in [0,64), flow_min_gain in [0,1], flow_cost >= 0 and finite, and min_saving_fraction in [0,1). (include/scaleli/index.hpp:66-77)
- [unchecked] **Region struct**: Region fields in declaration order: Key low_fence; vector<BlockDescriptor> blocks; vector<uint8_t> arena; vector<Value> values; vector<DeltaEntry> delta; LinearModel rank_model, byte_model (32 B each); double write_heat; bool raw_hot, flow_used; unsigned tail_conflicts_raw, tail_conflicts_flow; size_t virtual_points; vector<double> virtual_features; double rank_sse_before, rank_sse_after, smoothing_ns, transform_ns; unsigned choice; double cost_none, cost_selected. sizeof(Region) = 280 B on LP64/libc++. This follows from the layout (8+4x24+2x32+8+1+1+(pad 2)+4+4+(pad 4)+8+24+32+4+(pad 4)+16) and matches the audit, which reproduced metadata_bytes to the byte. The diagnostic fields are part of the 280 B charged per region. (include/scaleli/index.hpp:87-104; results/aidb_ba/memory_audit.md:21,31)
- [✓] **BlockDescriptor**: BlockDescriptor = {Key first, last; size_t rank_begin, count, offset, length; Codec codec (uint8_t); size_t slot_begin} = 64 B (7 B padding after codec). rank_begin is region-local. offset and length address the region's arena. slot_begin = rank_begin plus the virtual points before the block. At 200M the descriptors take 1,562,500 x 64 = 100,000,000 B = 0.5 B/key. (include/scaleli/index.hpp:79-84,234; include/scaleli/codec.hpp:14; results/aidb_ba/memory_audit.md:33)
- [✓] **Key arena**: Each region owns one std::vector<uint8_t> arena: its blocks' encoded bytes concatenated in key order. desc.offset = arena.size() when the block is appended, so offsets are region-local. Region::bytes(b) returns the span {arena.data()+offset, length}. (include/scaleli/index.hpp:91,115,234,236)
- [✓] **Delta buffer**: Each region has a sorted std::vector<DeltaEntry{Key key; Value value; bool deleted}> (24 B per entry with padding). It is searched by binary search, and set_delta inserts in sorted position or overwrites. upsert and erase compact the region once delta.size() >= delta_limit (default 64). With --profile read_only it is never written, so delta_bytes = 0. (include/scaleli/index.hpp:85,93,116-120,171-175,479-489; include/scaleli/workload.hpp:55; src/benchmark.cpp:274)
- [unchecked] **Region pointer vector / Index**: Index holds Config config_ (by value), std::vector<std::unique_ptr<Region>> regions_ (8 B per slot; each Region is its own make_unique heap object), size_, MaintenanceStats, root_model_ (LinearModel), root flags and costs, std::vector<uint32_t> root_slot_to_region_ and root_virtual_. sizeof(Index) = 336 B per the audit (also follows from the layout: Config 152 + 24 + 8 + 40 + 32 + 3 bools padded to 8 + 40 + 24 + 8). (include/scaleli/index.hpp:347-354,456; results/aidb_ba/memory_audit.md:18)
- [✓] **Encoding precedes modelling**: All blocks are encoded and appended (and the byte-position targets recorded) before any feature, flow, smoothing or model fit is computed. Codec choice reads only the keys, so key_bytes is identical across B, N, Nf, Cr and C for a given dataset. (include/scaleli/index.hpp:213-237 (encoding) vs 238-319 (features/targets/fit))
- [unchecked] **Codec common header**: Every block starts with a 16-byte header: byte 0 = codec tag (Raw 0, For 1, Delta 2, Linear 3); byte 1 = bit width w (For/Linear, else 0); bytes 2-3 = restart interval LE (Delta only); bytes 4-7 = key count LE uint32; bytes 8-15 = first key LE uint64. (include/scaleli/codec.hpp:14,88-90,97,111,119,144-146)
- [unchecked] **Raw codec**: Raw: header + n x 8-byte LE keys at byte 16+8i. Size = 16 + 8n, which is 1040 B per 128-key block, 33,280 B per raw region and 8.125 key B/key. (include/scaleli/codec.hpp:91-95,147-148; results/aidb_ba/memory_audit.md:113,148)
- [✓] **FOR codec**: For: w = bit_width(last - first), stored in byte 1. Key i is stored as (k_i - first) in w bits, LSB-first, starting at bit 128 + i*w. Size = 16 + ceil(n*w/8), which is 16 + 16w B at n = 128. Decoding is first + get_bits(...). (include/scaleli/codec.hpp:96-101,150-154,35-56)
- [unchecked] **Linear codec**: Linear: span = last - first is stored at bytes 16-23. The interpolation is floor(span*i/(n-1)), computed in 128-bit. Residual r_i = (k_i - first) - interp(i). lo = min r_i (int64) is stored at bytes 24-31. w = bit_width(max r - min r), and r_i - lo is packed in w bits from bit 256. Size = 32 + ceil(n*w/8). If a residual falls outside int64, the block falls back to Raw and is tagged Raw. (include/scaleli/codec.hpp:80-82,102-117,155-162)
- [unchecked] **Delta codec**: Delta: restart r (default 16) is stored at bytes 2-3. A table of ceil(n/r) uint32 LE byte offsets starts at byte 16. At each restart (i % r == 0) the full 8-byte LE key is written at the current end; other keys are a LEB128 varint of k_i - k_{i-1} (7 bits per byte, MSB = continuation). Size = 16 + 4*ceil(n/r) + 8*ceil(n/r) + sum of varint bytes. At n = 128, r = 16 that is 48 + 64 + varints for 120 keys. A random key_at decodes from the anchor of its restart group. (include/scaleli/codec.hpp:57-60,118-127,163-174; include/scaleli/index.hpp:45)
- [✓] **Codec policy**: Per block, selected = Raw. Under Forced, every block uses forced_codec (default For; Linear can still fall back to Raw). Under Raw, or when the region is hot, the block stays Raw. Otherwise For, Delta and Linear are tried in that order. A candidate replaces the current choice only if (a) bytes <= raw_bytes*(1 - min_saving_fraction), i.e. <= 988 B at n = 128 with the default 0.05, and (b) score(candidate) < score(selected), strictly. Under min_bytes, score = byte size, so the result is the smallest qualifying codec, with ties going to the earlier codec in the order Raw, For, Delta, Linear. (include/scaleli/index.hpp:216-233,48-49)
- [unchecked] **Smooth / adaptive policy**: For smooth and adaptive, score = |bytes - target|, where target = (16*ceil(N/B) + 8N) * (right - left)/max(1, span) * smooth_scale. N is the region's key count, B is block_keys, and span = last - first key of the region. left and right are midpoints between the block's edge keys and its neighbours' edge keys (0 and span at the region ends). In other words, the region's raw arena size is apportioned by key-span share. Adaptive additionally makes a region all-Raw while it is hot: the region enters hot when write_heat >= hot_enter (0.25) and leaves when write_heat <= hot_exit (0.05), with write_heat = 0.99*heat + 0.01*[write]. At bulk load hot = false. (include/scaleli/index.hpp:218-227,111-114,427,458)
- [✓] **Routing**: --routing does not change encoding or block boundaries, and both rank_model and byte_model are always fit and stored. Routing only selects what predicted_block uses. Rank compares rank_model.predict_x(feature) to blocks[m].slot_begin; Byte compares byte_model.predict_x(feature) to blocks[m].offset. The prediction is then corrected by exponential plus binary search on blocks[i].last. Binary skips the model and binary-searches blocks[].last. (include/scaleli/index.hpp:121-159,204-205,319)
- [✓] **Linear model**: LinearModel = {Key origin; uint64 span; double slope, intercept} = 32 B. fit_xy sets origin = keys.front() and span = max(1, keys.back() - origin). It then computes a single-pass Welford mean/co-moment in long double: slope = Sxy/Sxx (0 if Sxx <= 0) and intercept = mean_y - slope*mean_x, which is ordinary least squares. predict_x = fma(slope, x, intercept) and returns 0 if the result is non-finite. normalized(k) = (k - origin)/span as a double, negative below origin. (include/scaleli/model.hpp:11-42)
- [unchecked] **Model inputs and targets**: Feature x_i = (k_i - k_first)/max(1, k_last - k_first) per region, or flow(k_i) when flow_used. The rank model targets slots, which are region-local ranks 0..n-1 unless smoothed. The byte model targets positions_i = block offset + key_positions[i]: the byte coordinate (fractional for bit-packed codecs) of key i's first encoded bit within the region arena. key_positions are transient and not retained. Both fits happen after all blocks are encoded. (include/scaleli/index.hpp:235,242,283,290,319; include/scaleli/codec.hpp:76-78,203-218)
- [✓] **Query-time feature**: At query time Region::feature(k) returns flow(k) if flow_used, else rank_model.normalized(k). It uses rank_model's origin and span for both models, and these equal the temporary model's origin and span used at build time (keys.front()/back()). (include/scaleli/index.hpp:106-109,242; include/scaleli/model.hpp:30-31)
- [unchecked] **Virtual points in regions (C cell)**: smooth_cdf budget = size_t(alpha*n): 409 per 4096-key region at alpha 0.1, and 51 for the 512-key region, for at most 19,970,703 at 200M. Virtual points are never stored as records. Only their double features are kept in Region::virtual_features, at 8 B each in metadata. Their effect is to shift each real key's target to its slot (rank plus the virtual points before it), and each block's slot_begin = slot of its first key. (include/scaleli/smoothing.hpp:20-21,28-29,57,94; include/scaleli/index.hpp:101,311-315,340)
- [✓] **Virtual points vs final fit**: The final rank_model is fit with fit_xy(keys, x, slots) on the n real keys only; virtual points are not points in that regression. The CSV greedy loss that chose them, however, is the OLS SSE over real and virtual points together. The reported rank_sse_after is that augmented-set SSE (sm.sse_after), not the residual of the stored model. (include/scaleli/index.hpp:313,319; include/scaleli/smoothing.hpp:9-11,55-56,95)
- [unchecked] **Root virtual fences (Cr/C)**: With --root model and root_alpha > 0 and > 2 regions, fit_root smooths the region-fence features (only if they are sorted, so a non-monotone flow is excluded). It builds a uint32 table of n_regions + virt slots mapping slot to region, with budget size_t(0.1*48,829) = 4,882. The table is kept only if that candidate has the lowest probe cost and beats binary search, in which case it costs (48,829 + virt)*4 B, at most 214,844 B (0.00107 B/key; derived). Fence 0 used for fitting is region 0's first real key, not the sentinel 0. (include/scaleli/index.hpp:353,393-424; include/scaleli/smoothing.hpp:57)
- [unchecked] **Region::memory()**: Per region: key_bytes = arena.size(); value_bytes = values.size()*8; metadata_bytes = sizeof(Region) + blocks.size()*64 + virtual_features.size()*8; delta_bytes = delta.size()*24; reserved_slack_bytes = (arena cap - size) + (values cap - size)*8 + (blocks cap - size)*64 + (delta cap - size)*24. (include/scaleli/index.hpp:338-344)
- [unchecked] **Index::memory() and accounted_bytes**: Index metadata = sizeof(Index) + regions_.capacity()*8 + root_slot_to_region_.size()*4, plus the sum of the per-region fields. accounted_bytes() = key + value + metadata + delta + reserved_slack, which are live allocations excluding malloc overhead and RSS. At 200M the metadata is 336 + 8x48,829 + 280x48,829 + 64x1,562,500 = 114,063,088 B (0.570 B/key), observed in all 14 audited runs. (include/scaleli/index.hpp:534-538; include/scaleli/types.hpp:71-79; results/aidb_ba/memory_audit.md:29-33)
- [unchecked] **What memory() does not count**: Not counted: (1) the FlowTransform weights, since Config::flow is a bare pointer; they are reported separately as learnability.flow_bytes = sizeof(FlowTransform) + weights. (2) virtual_features capacity beyond size; it is absent from reserved_slack and never shrink_to_fit, and the protocol predicts 512 - 409 per region. (3) root_slot_to_region_ capacity, since only size() is counted. (4) Allocator overhead and size-class rounding. (5) The build-time copies. (include/scaleli/index.hpp:53,322,341-342,535; src/benchmark.cpp:119; include/scaleli/transform.hpp:62; include/scaleli/types.hpp:74; results/aidb_ba/PROTOCOL.md:158)
- [unchecked] **shrink_to_fit**: rebuild calls shrink_to_fit on arena, values and blocks only (a non-binding request). bulk_load shrinks the region pointer vector. memory() reports actual capacities, so any leftover shows up as slack (in metadata, for regions_.capacity()). (include/scaleli/index.hpp:321-322,467,535)
- [unchecked] **Bytes per key**: The protocol defines memory B/key as memory_before / source_rows (200,000,000), and analyze_ba.py divides by source_rows. tools/summarize.py's initial_bytes_per_key divides memory_before.accounted_bytes by initial_rows (post-dedup). The two agree only if the dataset has no duplicate keys. (results/aidb_ba/PROTOCOL.md:98; results/aidb_ba/analyze_ba.py:53,57; tools/summarize.py:46; src/benchmark.cpp:191-192)
- [✓] **SV reference memory**: sorted_vector stores one std::vector<Record> (16 B/key). Its memory() reports key 8n, value 8n, metadata sizeof(SortedVector) and slack (cap - size)*16. bulk_load also canonicalizes and calls shrink_to_fit. (include/scaleli/baselines.hpp:7-11,35)
- [unchecked] **When memory is sampled**: memory_before is taken right after bulk_load (and after the learnability read), before prefault, warm-up and the timed replay. memory_after is taken after the replay; memory_after_drain after maintain(). In read_only cells, maintain() returns immediately for every region, so all three are expected to be equal. (src/benchmark.cpp:111-142,212-213; include/scaleli/index.hpp:428,497)
- [unchecked] **Multi-threading (--build-threads)**: Only the per-region rebuild calls run in parallel: std::thread workers with a static interleaved partition (j = w, w+W, ...). Each writes only its own Region and reads config and flow. canonicalize (a stable_sort of the whole input), region-shell allocation and fit_root (including the root CSV smoothing over 48,829 fences) are single-threaded. build_ns is the wall clock of the whole bulk_load. Queries are single-threaded. (include/scaleli/index.hpp:65,453-467; src/benchmark.cpp:111,255)
- [unchecked] **Flow decision (N vs Nf)**: Under Manual fusion (the protocol default), N with --flow-bypass 1 keeps the flow in a region only if tail_conflicts_flow < tail_conflicts_raw and the drop is >= flow_min_gain (0.10) x raw. Nf (--flow-bypass 0) uses it in every region with more than one key. --flow-cost affects only Fusion::Auto and fit_root's root-candidate scoring, not the region decision. (include/scaleli/index.hpp:246,271,285-290,416; src/benchmark.cpp:270)
- [unchecked] **Compaction / rebuild**: compact(r) runs if the delta is non-empty, it is forced, or the hot state changed. It materializes base+delta through the merge scan. If rows > 2*region_keys (8192), it splits at rows.size()/2 into two new regions (the right fence is rows[mid].first), inserts them into regions_ and re-runs fit_root. Otherwise it calls rebuild(rows, config, hot, &region) in place, without refitting the root. bytes_rewritten += arena.size() + 8*values.size(). Block boundaries are again consecutive block_keys chunks. (include/scaleli/index.hpp:426-449,200-206)
- [unchecked] **relearn_on_compaction**: With relearn_on_compaction = false (default; --relearn 0), a compaction rebuild reuses the previous region's state. It copies tail_conflicts_raw, flow_used and tail_conflicts_flow (transforming only if the flow was in use), and skips Fusion::Auto. It re-places the old virtual_features among the new features in O(n+v) without a new smooth_cdf search, provided x is sorted, and drops them if the augmented SSE got worse. With true it re-runs the flow decision and the full smooth_cdf. (include/scaleli/index.hpp:57-60,208,244-246,281-283,296-310; src/benchmark.cpp:270)

# Lookup path, root and probe counters

A point lookup (Index::find, index.hpp:469-477) has three stages. (1) The root picks a region. It either binary-searches all region low_fences, or a global LinearModel predicts a region index (or, with --root-alpha, a virtual-fence slot that a uint32 slot->region table maps to a region), and an exponential search plus a binary search over the real fences corrects that guess. (2) Inside the region, the delta buffer is binary-searched. The region's rank_model then predicts a slot rank, a binary search over the block descriptors' slot_begin turns it into a block guess (coordinate_probes), and an exponential search plus a binary search over block max keys (BlockDescriptor::last) corrects the guess (fence_probes). (3) A plain binary search inside the block, using key_at on the compressed bytes, finds the key, and its value is read from values[rank_begin+lo]. fit_root adopts the learned root only if its measured probes per lookup on fences plus fence midpoints are strictly below binary search's; otherwise every lookup uses the binary root. Counters are collected only in the separate instrumented replay (Pass 4) through a non-null QueryStats*. The distinct 64-byte lines touched are counted in a 128-slot per-operation set, and new_operation() banks that count after each operation.

- **root fences are not a contiguous array**: There is no fence array. # NFL-style flow and CSV-style virtual points inside the index

In SCALE-LI the NFL-style flow is one global FlowTransform: a bias-free tanh MLP whose inputs are [x, x-floor(x)] with x=(key-mean)/var, followed by a sum decoder. Its output is only the FEATURE of each region's linear model, and of the root model if the root picks it. Records, fences and exact searches stay in key order, so a non-monotone flow is tolerated. Region-level adoption in the protocol's default --fusion manual mode is NFL's tail-conflict switch: the flow is kept if conflicts fall by at least 10%, or always when --flow-bypass 0. --flow-cost is ignored there and only charges the flow candidate at the root (and in the unused auto mode). CSV Algorithm 1 (smooth_cdf) runs after the flow decision, on whichever feature was chosen. It changes only rank TARGETS (slot ranks, through BlockDescriptor::slot_begin), with a budget of floor(alpha*n) points per region: 409 per full 4096-key region at alpha 0.1. At the root it builds virtual fences with a budget of floor(root_alpha*regions) plus a uint32 slot-to-region table, but only on monotone (sorted) fence features. A fence set is adopted only if its probe count on the fences and midpoints beats both the other candidates and binary search. In the per-cell numbers below, region counts and budgets assume 200M unique keys, which I did not check. Flow internals are hand calculations from the weight files, and the PROTOCOL figures were reported by earlier runs; I ran nothing.

# Benchmark harness, workload and baselines

scaleli_bench is one single-threaded C++20 process. It loads a SOSD file, sorts and deduplicates it with canonicalize, then generates the whole operation trace into memory before any index exists. It then runs up to four separate replays on fresh index instances: a timed throughput pass with no per-op timer or counters, an optional per-op latency pass, an optional differential verify pass against std::map, and an optional software-counter pass. Last it prints one JSON object. The timed region uses std::chrono::steady_clock and contains, per operation, the index lookup, a mix64 result checksum and digest update, and K+1 extra timestamps for the chunk curve. Build (build_ns, which includes copying and re-sorting the 200M input), prefault, warm-up and memory snapshots are timed separately or not at all. Of the PROTOCOL 4.1 flags, the current benchmark.cpp implements --index, --instrument, --qos, --chunks, --prefault, --warmup-mode, --seed, --ops and --warmup. It rejects --interleave, --rounds, --visit-warmup, --visit-ops, --sub-chunks, --cooldown-s, --go-dir, --cycles, --probe-latency-mb, --freq-probe, --root-gaps and --root-gaps-mode as unknown options. These are patches P1/P2/P6/P3 that PROTOCOL 8.1 still schedules. So today only the D-layer command line can run; the X-layer and P-layer lines cannot. The baselines are a 16 B/key array-of-structs sorted_vector searched with std::lower_bound, and a std::map behind a counting allocator. ALEX and dynamic PGM are compiled only with SCALELI_EXTERNAL=ON, which is off by default and off in the protocol build.

- **Q:** What does steady_clock resolve to on macOS?

- **Q:** Will Linux (libstdc++) reproduce the same trace, fingerprint and checksum for a given --seed?

This is unverified, since nothing was run. (include/scaleli/workload.hpp:110-113, 145, 158)
