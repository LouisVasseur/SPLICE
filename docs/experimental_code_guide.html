A reading route for the C++20 index, its Python experiment tools, and the decisions to discuss with a supervisor.

The five-minute explanation

This is C++20, not C. The in-process ordered map and benchmark execute in compiled C++. Python manages datasets, launches benchmark processes, analyzes output and runs small mathematical experiments. The default engine has no PyTorch, TensorFlow, neural flow, or GPU dependency.

The prototype stores exact unsigned 64-bit keys and values. Keys are losslessly compressed in independently rebuildable regions. Small affine models predict logical rank or an encoded coordinate; exact key fences and decoding recover the correct result. Writes enter a sorted overlay and are merged synchronously into the base when a threshold is reached.

Research hypothesis, not an established speedup: Can selective compression improve physical routing enough to repay directory search, decoding, value access and maintenance? Compressing the same keys does not change their logical ranks.

The engineering reason for using C++ is to study real byte layouts, native integer arithmetic, allocation and search costs without a Python dispatch on each operation. C++ is a practical choice, not a proof of optimal speed; the code still has scalar decoding, allocation costs and synchronous rebuilds. Its __int128 requirement limits portability.

Python suite → C++ benchmark main → data/trace preparation (not timed)
                                      ↓
                                  fresh Index

                ordered region directory (exact binary search)

             Region = compressed base + sorted update overlay

Not implemented: NFL/AFLI, full CSV integration, a learned cost selector, reinforcement learning, neural routing, variable-length payloads, concurrent operations, persistence or online merging of empty regions. Optional ALEX/PGM adapters are separate baseline integrations and were unvalidated in the shipped release.

Keep these distinctions straight

TermsDistinction
Region vs blockA region is an ownership/rebuild unit (default 4,096 keys at bulk load). A block is an encoding/search unit (default 128 keys).
Routing vs compressionThe router maps key → position. The linear codec maps local position → predicted key, then adds an exact stored residual.
Logical rank vs byte coordinateCompression does not change rank. Encoded offsets depend on actual codec lengths; bit-packed coordinates may be fractional byte positions and are only hints.
Delta overlay vs delta encodingThe overlay stores recent mutations/tombstones. The codec stores consecutive key gaps. They are unrelated uses of the word delta.
Index storage vs harness storageThe index retains no full uncompressed base-key copy. The harness retains input/trace/reference data outside index storage; process memory is therefore much larger than accounted index bytes.
Policy vs routerMinBytes chooses sizes, Smooth chooses a density-derived byte budget, Adaptive adds raw-hot hysteresis. Binary/Rank/Byte independently choose how to locate a block.

Correctness must survive a bad prediction

Ownership intervals are disjoint and ordered. Base keys remain sorted. A unique overlay entry supersedes the base record. Every model hint is resolved through exact boundaries and decoded keys. These protect map semantics; they do not imply bounded latency, transactions or crash recovery.

What to present at the meeting

Implemented: an exact compressed mutable map, three routing controls, four lossless codecs, local buffering/rebuilding, standalone geometry controls and a paired benchmark harness.

Observed in the posted Mac run: the synthetic 50,000-key, 20,000-operation run passed differential verification; it showed compact key storage and expensive compaction-triggering writes. This is not a real-dataset or SOTA comparison.

Next experiment: hold layout and trace fixed when comparing rank versus byte routing; hold routing fixed when comparing raw versus compressed storage. Measure directory/decoding work and maintenance as well as fitting error.

Candidate future learning: a rebuild-time codec/layout cost selector and search-aware small models. The existing enum Policy::Adaptive is an EWMA/hysteresis heuristic, not a trained AI controller.

Implementation details to audit: both rank and byte models are fitted even for Binary controls; predicted_block still binary-searches a directory; mutations can rebuild a whole region; scans allocate/materialize output; the encoded-byte coordinate is not a pointer; software counters exclude some internal maintenance work. These facts limit what can be attributed to model accuracy.

35## Memory scope
36
37`memory_before`, `memory_after`, and `memory_after_drain` contain:
38
39- `key_bytes`: live encoded arenas, including per-block headers and delta restart tables; raw baseline keys occupy eight bytes each.
40- `value_bytes`: live uncompressed uint64 payload column, including base records later shadowed by tombstones until compaction.
41- `metadata_bytes`: object sizes, block descriptors, models, root pointer capacity, configuration and counters. Descriptors contain exact fence keys; they are not free.
42- `delta_bytes`: live update-buffer entries including padding and tombstones, not just key/value content.
43- `reserved_slack_bytes`: actual vector capacities beyond live sizes. `shrink_to_fit()` is non-binding and not assumed to succeed.
44- `accounted_bytes`: sum of the five components.
45- `estimated`: true for external native-size approximations whose accounting differs.
46
47Core accounting excludes malloc headers, allocator fragmentation, stack, temporary compaction buffers, workload vectors, source dataset copies, query output vectors, and process runtime. `std::map` uses an allocation-counting allocator for tree nodes, but its allocator-control object is not a general RSS measurement. Run each index in its own process and collect steady/peak RSS plus allocator statistics for publication-quality memory results. Include transient compaction memory separately rather than replacing the steady-state measure with it.
48
49`key_arena_ratio = key_bytes / (8 × initial_rows)` is key-only and can exceed one because of headers. `accounted_bytes / live_rows` is full-index accounted bytes per live key. A tombstone-heavy index needs both measures.

51## Work and maintenance counters
52
53`root_probes`, `coordinate_probes`, `fence_probes`, `delta_probes`, and `key_at_calls` count logical comparisons/accesses in their respective code paths. `decoded_keys` and `codec_bytes_examined` are software decoding-work measures; header reads and CPU/cache behavior are not comprehensively modeled. `blocks_decoded_for_scan` counts scan block expansions.
54
55`correction_distance` is the sum of absolute block-index displacements from learned candidates to exact corrected results. Divide by `block_routes`, not by all operations. `max_correction_distance` is a worst observed displacement. Binary routing has no learned candidate, so these fields are zero and not comparable as model accuracy.
56
57Maintenance `bytes_rewritten` counts newly written key-arena bytes plus eight bytes per rebuilt base payload. It excludes metadata writes, reads, allocator traffic, temporary materialization, and bytes merely moved in the delta. It is therefore a **logical lower-bound proxy**, not hardware write amplification. `max_rewrite_bytes` is the largest one-rebuild proxy. Compaction and split counters exclude initial bulk loading. `raw_bypasses` counts hot raw rebuild events, not distinct regions.
58
59`drain_ns` and `drain_additional_rewrite_bytes` quantify pending maintenance after the timed run. Also report end-to-end amortized throughput using `(elapsed_ns + drain_ns)` when comparing sustainable workloads. Repeated updates to the same key may leave a tiny delta and postpone a representation transition indefinitely; the explicit drain reveals that condition.
60
61## Statistical interpretation
62
63`run_suite.py` randomizes job order, executes a fresh process per variant/seed/repeat, records commands, compiler/CPU metadata and the benchmark binary SHA-256, and refuses to overwrite results. Optional Linux `--cpu` uses `taskset`; it does not set NUMA placement, governor, or frequency.
64
65`summarize.py` rejects unmatched trace fingerprints across variants. It reports per-group medians and paired throughput ratios against `raw_rank` by default. Ratios are summarized in log space, and bootstrap intervals resample **seed clusters**, not millions of individual queries. With fewer than two independent seeds, interval endpoints are NaN. The included two-seed smoke intervals are exploratory and should not be used for significance claims. Use at least five seeds, repeated process runs, predefined datasets, and confidence intervals for the actual claim being made.
66
67The default benchmark does not report P99.9/P99.99, hardware PMU events, physical disk I/O, energy, queueing latency, or out-of-process memory peaks. Those are explicitly proposed extensions, not hidden in existing fields.
